# AI Agent入门

## Agent = LLM + 上下文 + 工具

我们将Agent看作一个人的话，**LLM**就是大脑（负责决策和思考），**上下文**就是眼睛（接受环境提供的观察），**工具**就是手脚（将决策转化为作用于环境的行动）。

**Agent = 大脑 + 眼睛 + 手脚**

**LLM**：大语言模型（**Large Language Model**）。LLM是Agent的**决策内核**，就像人脑一样起到一个**理解意图、思考规划、做出判断**的作用。其能力来自**预训练**积累的世界知识与语言能力，及**后训练**（监督微调与强化学习等技术）固化的决策策略。

**上下文**：Agent在每个决策点收到并保留的**信息表示**（包括**来自环境的观察、用户记忆、领域知识、自身状态和任务进展**）。

**工具**：Agent感知或改变世界的**接口**，包括**工具定义、调用协议和适配器**。

```markdown
- 环境状态也可以被读取、筛选并编码进上下文，上下文≠环境。
- 工具背后的文件系统、数据库、网页、用户或物理世界也仍属于环境。
```

------

**Agent的最小交互结构**：

- 在经典的强化学习和控制论视角下，Agent与Environment是闭环交互的两方，彼此独立。
	- 循环过程：
		1、环境向Agent返回当前观察
		2、Agent根据已有上下文进行下一步行动
		3、行动改变环境状态
		4、新状态产生下一次观察、
		5、循环继续进行
		
		```markdown
		- 环境包括：文件、数据库、网页、用户、其他 Agent、物理或仿真世界
		- Agent通过观察接口和行动接口与环境交互
		```
	
- 两个抽象层次：
	- 外层 Agent <-> Environment
	
	- 内层 Model-Harness
	
	  ```markdown
	  - Model负责决策。
	  - Harness：Agent边界内环绕模型的运行与治理层。
	  	- 构造上下文
	  	- 暴露接口工具
	  	- 维护循环和状态
	  	- 实施权限、验证与纠正
	  ```



综上，**Agent = LLM + 上下文 + 工具** 此公式可展开为： **LLM** 对应Model，而 **上下文 + 工具** 构成最小Harness；生产系统中，会在Harness中加入约束、验证和纠正。



## 观察空间与动作空间

观察通道与动作接口构成了`Agent`与外部环境之间的边界。

**模型固定时，Agent任务表现的提升是重新定义或扩展观察空间与动作空间（即扩展上下文和工具）。**

`Harness`构造上下文 -> 模型处理 -> 模型选择行动 -> 调用工具影响环境

`Manus`将 `Deep Research（深度调研）`、`Coding（代码生成）`和 `Computer Use（电脑操控）`三条相对独立的路线合并，使同一个`Agent`拥有了更大的观察空间与动作空间，从而使得同一个`Agent`能跨越原有产品边界完成任务。

`OpenClaw`本地优先。数字文件由用户进行授权，进入同一个`Agent`的观察空间。`OpenClaw`相比于早期以隔离云端沙盒为中心的`Manus`，无需上传文件或额外配置连接器。`OpenClaw`把接口延伸到了用户的数字生活中，把观察空间和动作空间向外推进了一层。

### 工具调用的流程

**工具调用（Tool Calling，也叫Function Calling）是现代LLM Agent的一项核心能力，让模型通过结构化方式调用外部工具。这也使得LLM转变为可以执行实际操作的智能系统。**

- 1、在上下文中告诉模型可用的工具（包括名称、用途和参数）
- 2、模型自主判断是否调用工具、选择哪个工具、传什么参数
- 3、工具执行完毕，结果追加到上下文中
- 4、模型据此决定下一步行动

**此循环也是ReAct的基础**。



## LLM

LLM是Agent决策核心，其“理解-规划-执行”的能力表现为：

LLM -> 收到用户请求 -> 解析真实意图 -> 将任务拆解为可执行的步骤  -> 执行过程中还需持续做出判断（下一步该做什么、是否调用工具、调用哪个工具、传什么参数）

LLM Agent具有**内部思考**的独特能力。即Agent在实际行动前，先进行规划与推演。

```markdown
- “理解-规划-执行”的能力是工作流和自主Agent的基础，来自预训练积累的知识。
- LLM能进行有效的内部推演也得益于预训练，模型推演遵循的是人类知识中沉淀下来的逻辑规则（数学定律、因果关系、问题分解策略等）。
```



**模型即Agent**：模型通过后训练（强化学习）将工具调用能力内化为原生能力，自主决策工具调用。

Harness是用来引导模型能够可靠执行任务，Harness应该同模型协同优化，持续迭代，减少模型出错时所造成的影响。 Harness是对模型尚未内化能力部分的兜底约束，倘若模型已将某能力彻底内化，那么Harness则会转去兜底新的能力前沿。



**Agent的学习机制**：上下文适应  ->  持久更新。

- **任务内上下文适应。**示例、状态和检索结果进入上下文后，影响模型调整行为，但不影响下次绘画的持久状态。

- **外部产物更新。**知识文档、 Prompt 或 Skill、程序和 Harness。这些外部产物可审计、可修订，执行时Agent通过上下文或工具接口使用。
- **模型参数更新**。参数更新能够形成自然、广泛的泛化能力。

```markdown
- Tool是Agent可以调用的具体函数、API脚本。只负责“执行”，不负责“思考”。
- Skill是一套结构化的完整流程，告诉 Agent：在什么场景下，按照什么步骤，以什么参数去调用哪些工具。
```



## 上下文

调用LLM时的上下文由以下五个部分构成：

- **系统提示词（System Prompt）**：由开发者编写，整个对话过程中保持不变。定义Agent的身份、权限和行为准则。
- **工具定义（Tool Definitions）**：声明 Agent 可用工具的名称、功能描述和参数格式。
- **用户消息（User Messages）**：来自用户的输入。
- **模型回复（Assistant Messages）**：模型之前生成的回复，最多包含三个部分，即思考过程（reasoning）、文本内容（content）、工具调用请求（tool_calls）。
- **工具执行结果（Tool Results）**：Agent框架执行工具后返回的结果。

```markdown
- 系统提示词中还会包含跨会话保存的用户记忆（用户偏好、历史行为、背景设定等个性化信息）
- 没有工具定义，Agent就无法识别和调用任何工具。
- 用户消息中还可能包含通过RAG检索引入的外部知识。（覆盖训练数据截至后的 信息 or 私有领域知识）
- 模型回复的三个部分
	- 思考过程，即内部思考链，保持思维连贯性和决策可解释性
	- 文本内容，即对用户的回复
	- 工具调用请求，即Agent采取行动的方式
- 模型回复的三个部分不一定同时出现
	- Agent决定调用工具时，通常只有reasoning + tool_calls
	- Agent给出最终回答时，通常只有 reasoning + content
- 工具执行结果是Agent下一步思考的依据，也可以使它从执行结果中学习、避免重复犯错
```



## ReAct循环

**ReAct** **=** **Reasoning** **+** **Acting**

ReAct实际循环（想→做→看→想→做→看）：模型思考当前应该做什么  ->  调用工具行动  ->  观察工具返回的结果  ->  继续思考下一步

```markdown
- Agent轨迹是在执行任务过程中不断积累的消息历史（用户消息、模型回复、工具执行结果）
- 静态前缀 = 系统提示词 + 工具定义
- Agent的上下文 = 静态前缀 + 轨迹
```
